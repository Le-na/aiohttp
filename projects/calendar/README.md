# Календарь семьи — веб-календарь с днями рождения, задачами и печатью

## Что это

Сайт, где один человек (я) регистрируется, настраивает календарь и получает
личную ссылку. Ссылку скидываю родным и друзьям — они открывают её без
всяких регистраций и заполняют дни рождения и задачи. Потом весь год
(или месяц) можно распечатать красивым плакатом и повесить на стену.

Идея родилась из личной потребности: у нас большая семья, дни рождения
разбросаны по всему году, все держат их в голове и каждый раз переспрашивают.
А ещё я хочу научиться делать настоящие сайты на Python — этот проект мой
учебный полигон и одновременно вещь, которой семья будет пользоваться.

## Что уже работает (сентябрь 2026)

- REST API на aiohttp: сохранить запись (PUT), удалить (DELETE),
  прочитать месяц (GET). Проверено curl и живой страницей.
- Страница-календарь одного месяца (октябрь 2026): клик по дню — окно
  ввода, текст заметки виден прямо в ячейке.
- 15 цветовых тем из «Японского справочника сочетаний цветов» Сандзо Вады
  («A Dictionary of Color Combinations», 1933). Это приятный бонус для
  пользователей — выбираешь любую, чтобы было уютно заполнять таблицы.
  К итоговой печати эти темы НЕ имеют отношения — дизайн печати отдельный.
- Страница и API уже соединены: страница пишет и читает через сервер,
  заметки лежат в хранилище сервера (пока в памяти).

## План развития (дорожная карта)

### Этап 0 — закрепить сделанное
Тесты pytest на API, первый коммит в git.

### Этап 1 — SQLite: данные переживают перезапуск
Три таблицы: notes (записи), birthdays (дни рождения), tasks (задачи).
Сервер перезапускали — записи на месте.

### Этап 2 — регистрация и вход
Один владелец регистрируется: имя + пароль (пароль хранить правильно —
одностороннее преобразование). Вход → сервер выдаёт «значок» (токен),
middleware проверяет его на владельческих роутах.

### Этап 3 — личная ссылка для гостей
/c/Xk7f2a — ссылка с кодом. Гости без регистрации открывают и заполняют.
Мама, брат, подруги — просто по ссылке.

### Этап 4 — весь год или месяц
Выбор владельца: показывать календарь года (12 маленьких таблиц)
или один месяц. API уже готов почти целиком — GET /notes/{year}
отдаёт все записи года, структура адресов это умеет.

### Этап 5 — мастер дизайна: кнопка «Дальше»
Настройка итогового вида: тема печати, свои фотографии, формат.
Это уже данные профиля (print_design), а не «приятный бонус».

### Этап 6 — PDF: печать
Три формата на выбор:
1. Гигантский годовой плакат — как ватман или больше,
   горизонтальный или вертикальный.
2. Обычный месячный — А4/А3, горизонталь или вертикаль.
3. ОТРЫВНОЙ — по одному дню на листок, 365 листков.
Пользователь печатает сам или через печатные сервисы.

### Этап 7 — печатные сервисы
Страница со ссылками на типографии, куда можно отправить свой PDF.

## Данные: три сущности, которые не путаются

- **Запись (note)** — событие конкретного дня: «купить тортик».
  Привязана к году, месяцу, дню. В следующем году её нет.
- **День рождения (birthday)** — не событие, а свойство человека:
  имя, фамилия, дата рождения. Повторяется каждый год сам собой,
  потому что он не «записан на 2026», а просто вечный.
  Возраст НЕ хранится — вычисляется на лету:
  текущий год минус год рождения (минус один, если день ещё не наступил).
  Хранить возраст нельзя — он бы устарел через год.
- **Задача (task)** — из todo-листа: зачёты и экзамены, «каждый месяц
  в аквапарк с ребёнком». Пока повторяющиеся задачи ставлю руками
  на каждый месяц — когда надоест, придумаю автоматизацию повторов.

Принцип: вычисляемое не хранят. Данные не зависят от оформления —
тема заполнения и дизайн печати это разные вещи.
